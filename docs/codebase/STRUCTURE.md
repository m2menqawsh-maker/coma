# Codebase Structure

## Core Sections (Required)

### 1) Top-Level Map

| Path | Purpose | Evidence |
|------|---------|----------|
| `src/` | Main application source code (App router pages, UI components, business logic, integrations) | `tsconfig.json:22`, `src/app/` |
| `src/app/` | Next.js App Router routes, page layouts, route handlers, and domain components | `src/app/layout.tsx`, `src/app/page.tsx` |
| `src/components/` | Global UI components, shared layout (`AppLayout.tsx`), dashboard widgets, and offline/privacy providers | `src/components/` |
| `src/lib/` | Reusable utilities, offline sync engine, financial calculation engines, and Supabase client factories | `src/lib/` |

| `supabase/` | Supabase CLI project metadata and configuration state | `supabase/.temp/` |
| `schema.sql` | Complete database schema dump (tables, views, enums, triggers, RLS policies) | `schema.sql` |
| `docs/codebase/` | Architecture and codebase onboarding documentation generated by scan | `docs/codebase/` |

### 2) Entry Points

- Main runtime entry: `src/app/layout.tsx` (wraps application with `OfflineSyncProvider` and `PrivacyProvider`, defines viewport and metadata).
- Secondary entry points (worker/cli/jobs):
  - Service Worker: Auto-generated into `public/sw.js` via `@ducanh2912/next-pwa` config in `next.config.ts`.
  - Backend API route: `src/app/api/users/route.ts` (POST handler to provision user auth and profiles via Supabase Admin).
  - Auth route guard middleware candidate: `src/proxy.ts` (contains Next.js request redirect logic, though currently misnamed as `proxy.ts` instead of `middleware.ts`).
- How entry is selected:
  - Selected by Next.js App Router file-system convention (`src/app/**/page.tsx`).

### 3) Module Boundaries

| Boundary | What belongs here | What must not be here |
|----------|-------------------|------------------------|
| `src/app/[feature]/` | Feature views, specific modals/tabs, local types (`types.ts`), and local formatters (`utils.ts`) | Generic utilities shared across multiple features, direct secret keys |
| `src/lib/finance/` | Pure financial calculation functions (session costs, invoice rounding, debt, gross profit, obligations) | React JSX, DOM manipulation, state hooks, direct database mutations |
| `src/lib/offline/` | Connection state management, offline request queueing, heartbeats, and storage persistence | Feature-specific business rules, page styling |
| `src/lib/supabase/` | Browser & server Supabase client instantiation, URL-based cache reads/writes/eviction | Direct React UI rendering |
| `src/components/` | Reusable UI layout elements, global providers, shared modals (`DoubleConfirmModal`), dashboard widgets | Feature-specific mutations that belong in actions or services |
| `src/app/api/` | Server-only operations requiring administrative service credentials (e.g. `SUPABASE_SERVICE_ROLE_KEY`) | Client React components, non-secure public operations |

### 4) Naming and Organization Rules

- File naming pattern:
  - React components: PascalCase (e.g., `AppLayout.tsx`, `CheckoutModal.tsx`, `InvoiceDetailsModal.tsx`).
  - Pages & layouts: Next.js conventions (`page.tsx`, `layout.tsx`, `route.ts`).
  - Utilities and libraries: camelCase (e.g., `calcCost.ts`, `exportCsv.ts`, `cache.utils.ts`, `offlineStateManager.ts`).
  - SQL migrations: Sequential numbers with descriptive names (e.g., `001_fix_bank_double_counting.sql`, `004_add_flexible_subscriptions.sql`).
- Directory organization pattern:
  - Feature-sliced structure under `src/app/` (e.g., `src/app/sessions/` contains `components/`, `actions/`, `types.ts`, `utils.ts`, `page.tsx`).
- Import aliasing or path conventions:
  - `@/*` aliases directly to `./src/*` (`tsconfig.json:22`).

## Extended Sections (Optional)

### Feature Subdirectory Map

- `src/app/sessions/`: Active table & floor management, device switching (mobile/laptop/pause), order taking, checkout modals, and financial calculations.
- `src/app/invoices/`: Historical invoices, debt management, customer balance accounts, partial payments, and settlements.
- `src/app/subscriptions/`: Flexible subscription plans (hours/days limit, drink allowances, date freezing, usage logs).
- `src/app/banks/`: Bank accounts (PalPay, JawwalPay, BOP, ISBK), transfer tracking, pending deposit confirmations.
- `src/app/expenses/`: Categorized operational, fixed, purchase, and loan repayment expenses.
- `src/app/inventory/`: Raw items, retail products, multi-ingredient recipe definitions, and purchase stock increments.
- `src/app/ledger/`: General financial journal tracking every cash and bank monetary flow.
- `src/app/closing/`: Step-by-step financial closing wizard (`ClosingWizard`), period profit calculations, partner share snapshots, and period locking.
- `src/app/partners/`: Partner profiles, capital contributions, withdrawals, loans, and profit percentages.
- `src/app/obligations/`: Recurring fixed commitments (rent, utilities, salaries) with daily amortized rates.
- `src/app/reports/`: Month/day profit & loss reports, revenue channels, and KPI breakdowns.
- `src/app/settings/`: Core system pricing (mobile/laptop rates, place costs, dev cuts), packages, bank accounts, and catalog items.
- `src/app/tracking/`: Real-time system audit logs (`activity_logs`) capturing user activities across invoices, sessions, expenses, and inventory.
- `src/app/users/`: Staff and partner user account administration and role assignment (`admin`, `partner`, `viewer`).
